# Armillae RFC 工作流

RFC 用于记录尚未确认、需要讨论或会改变架构边界的工程提案。已经生效并持续约束实现的契约
放在 `../specs/`；技术验证证据放在 `../spikes/`；RFC 本身不代替实现清单。

## 状态

- `Draft`：正在探索或讨论，不构成实现授权，也不得产生实施 TODO。
- `Accepted`：核心决策、范围和验收标准已经确认，可以同步 Active Spec 并建立实施清单。
- `Active`：RFC 本身被持续维护为现行架构决策；具体公共契约仍应落入相关 Spec。
- `Rejected`：提案未采用，保留其背景与原因供后续参考。
- `Superseded`：提案已被后续 RFC 替代，必须链接替代文档。

## 编号与推进

RFC 文件使用四位递增编号和简短主题，例如 `0001-agentic-runtime.md`。新提案先以 Draft 创建，
明确问题、目标、非目标、候选方案、影响、验收标准和待决问题。只有用户明确确认关键边界后，
才能转为 Accepted；接受后按 `.agents/DESIGN.md` 规定的顺序同步 Spec、TODO、实现与用户文档。
